## 概覽

一眼看到自己與所屬組織 repo 的 GitHub Actions 執行狀況，重點是確認 CI 綠燈了沒。Windows 常駐工具（WPF／.NET 10），常駐系統匣。

系統匣圖示的顏色加形狀，就能回答「現在有沒有紅的、有沒有在跑的」，不必開視窗。

- **系統匣**：有失敗是紅底 ✕、有進行中或排隊是黃底「…」、全部成功是青綠底 ✓；連線有問題時加「!」角標。
- **主畫面**：每個監看中 repo 最近 30 筆 run，可以篩選、搜尋、只看需要注意的；進行中的 run 顯示已執行時間與預估剩餘時間。
- **提示**：追蹤中的 run 失敗、你觸發的 run 成功、你標記的 run 完成，或有新版本時，螢幕右下角跳出提示，不搶焦點。
- **省額度**：輪詢只送 `GET`，有 ETag 就帶上；沒有變化時 GitHub 回 304，不扣主額度。
- **重跑與取消（預設關閉）**：在設定頁開啟寫入功能後，run 選單可以重跑失敗的 job、整個 run 重跑、取消、強制取消，每次都先確認。預設唯讀，開啟寫入功能後才會送 `POST`。
- **命令列**：`IsItGreenYet-cli.exe status --json` 讀 App 寫的狀態，輸出一行 JSON，用退出碼表示整體狀態（和系統匣一致），給腳本用。
- **認證**：沿用 gh CLI 的登入，或改用 fine-grained PAT（只看狀態時給唯讀權限即可）。
- **介面語言**：繁體中文、English，在設定頁切換，按「儲存」後立即換。
- **不需要安裝程式**：單一執行檔，裝好 .NET 10 Desktop Runtime（見 [README 的系統需求](../README.zh-TW.md#系統需求)）之後，複製到資料夾就能執行。不要放在別人或瀏覽器能寫入的資料夾（例如下載資料夾），exe 旁邊的同名 DLL 或 `gh.exe` 會被載入。

## 範圍

- **只看 GitHub Actions 的 workflow runs**。Actions 以外的外部 check（例如 Cloudflare、Zeabur 這類掛在 PR 上的 check run 或 commit status）不在範圍內。
- **預設唯讀**：只送 `GET`。在設定頁開啟寫入功能後，才能在 run 選單重跑、取消 run（送 `POST`，token 要有寫入權限，見[寫入功能需要的權限](authentication.zh-TW.md#寫入功能需要的權限)）。
- 不做單一 job 重跑、批次「全部重跑」或「全部取消」，提示視窗與系統匣選單上也沒有重跑、取消的按鈕。
- 不用 webhook：webhook 需要對外可達的接收端，桌面常駐程式沒有，所以只能輪詢。
- 不做依 workflow 靜音（只有 repo 層級的靜音）與安裝程式。有新版本時只會提示，程式不會自己下載或替換：要升級就替換 exe。

## 常用操作

| 想做的事 | 怎麼做 |
|---|---|
| 看整體狀態 | 看系統匣圖示：失敗是紅底 ✕、進行中或排隊（含等待核准）是黃底「…」、全部成功是青綠底 ✓、無資料是灰底「–」。第一次執行或快取資料庫重建之後，清單和各 repo 全部查完之前不會先變成全部成功，是灰底（失敗與進行中照常顯示；補抓失敗的例外見[已知限制第 33 項](known-limitations.zh-TW.md)）；清單一直抓不回來就一直是灰底，單一 repo 一直查不到時最多等 1 小時。右下角的「!」角標代表連線問題（未登入、被限流、離線、GitHub 持續回 5xx、API 版本停止支援）。滑鼠停在圖示上看 tooltip：第一行 `IsItGreenYet`，第二行「N 進行中 · M 失敗 · 更新於 HH:mm」，有連線問題或無法更新的 repo 時再加一行原因；剛啟動、還沒有第一份資料時只有 `IsItGreenYet` |
| 開主畫面 | 左鍵點系統匣圖示，或右鍵選「開啟」；程式已經在跑時再執行一次 exe，也會喚回既有視窗。命令列 `IsItGreenYet-cli.exe` 是另一個執行檔，不經過 App 的單一實例檢查，執行它不會喚回視窗（見[命令列](cli.zh-TW.md)） |
| 系統匣右鍵選單 | 依序 7 項：開啟｜立即刷新、暫停自動更新（暫停中顯示「恢復自動更新」）｜repo 管理、設定、開啟資料夾｜結束（「｜」是選單裡的分隔線）。選單和主畫面一樣是深色，Windows 11 上有圓角與陰影 |
| 篩選清單 | 篩選列的 Repo、Workflow、Event、Status、Branch、Actor 六個多選：同一欄位內是「或」、不同欄位之間是「且」；有勾選時按鈕顯示數量，例如「Repo（2）」。有任何篩選、搜尋或「只看需要注意」在作用時，篩選列最後出現「清除篩選」。篩選偏好會保存，搜尋文字不保存。篩選只影響清單，不影響摘要列的計數與系統匣 |
| 搜尋 | `Ctrl+F`，比對 repo、標題、workflow 名稱、分支，不分大小寫；搜尋框有焦點時按 `Esc` 清空 |
| 只看要處理的 | 勾「只看需要注意」：追蹤中失敗的 run，加上所有未完成與等待核准的 run |
| 立即刷新 | `F5`、系統匣右鍵「立即刷新」，或橫幅的「立即重試」（離線、GitHub 回應異常時才有） |
| 調整自動更新 | 摘要列右邊的「自動更新」下拉：自動（預設）、30 秒、1 分、5 分、暫停。**固定秒數會取代自動模式的間隔**：push 探測、每個 repo 的 runs 輪詢（連有 run 在跑、自動模式下 15 秒一次的 repo 也一樣），以及追蹤中、標記「完成時通知我」的 run 的單筆更新，都改用這個秒數，所以選「5 分」時新 run 最多約 5 分鐘才出現；PR 清單、workflow 清單與 repo 完整清單照原本的週期，低額度拉長與鎖定時的下限照樣套用。「暫停」時不做任何週期性輪詢，只有 F5／「立即刷新」、命令列 `--refresh`，以及解鎖、喚醒、離線恢復、重新登入時會全量刷新一次。系統匣右鍵可以暫停／恢復（恢復到暫停前的模式）；選擇存進 `settings.json`，重啟後維持，包括暫停。檢查新版本有自己的設定，暫停時照常檢查（見下方的「檢查新版本」） |
| 開啟網頁 | 點 repo 名稱開該 repo 的 Actions 頁；點觸發說明裡的 PR 編號或 commit、分支 chip 開對應頁面；選取一列按 `Enter` 開該 run。只開 `https://github.com/` 開頭的網址，其他網址不開，顯示訊息並寫 error.log |
| 更多操作 | 每列最右邊的 ⋯ 按鈕、右鍵或 `Shift+F10`：開啟 run、開啟 PR（有 PR 編號時）、開啟 commit、複製 run 網址、複製失敗 log（失敗的 run）、這筆完成時通知我（未完成或等待中的 run）、靜音此 repo。開啟寫入功能時，後面另有一條分隔線與「重跑失敗的 job」「整個 run 重跑」「取消這次執行」三項，以及取消受理超過 5 分鐘仍未完成時才出現的「強制取消」（見下一列）；寫入功能關閉（預設）時沒有這些項目，也沒有分隔線 |
| 重跑或取消 run | 先在設定頁「寫入操作」勾「允許在 App 內重跑與取消 run」並儲存（預設關閉；關閉時不送任何 `POST`）。⋯ 選單選一項後跳出確認對話框，寫明是哪一筆（`repo · workflow #編號`、第幾次嘗試、分支）與這個動作的影響；預設焦點在「不要」，`Enter` 不會執行，`Esc` 等於「不要」。確認後訊息條顯示「正在送出…」；已受理（例如「已送出重跑。」）與沒有送出（例如「目前離線，沒有送出。」）顯示在訊息條，被 GitHub 拒絕與結果不確定（沒有收到回應，或 GitHub 回 5xx：可能已經生效，App 會自動確認）用錯誤對話框。現在不能做的項目會停用，滑鼠停在上面看原因（例如還沒完成、已完成、workflow 已停用、超過 30 天、可能已達重跑上限、目前離線、缺少權限）。取消受理後，這一列的狀態與時間欄顯示「取消中」，直到 run 真的完成（重新啟動 App 後不再顯示；視窗窄於 `777` 時，進行中的列見[已知限制第 35 項](known-limitations.zh-TW.md)）。在 App 內重跑的 run，新的一次完成時會自動跳提示（照「完成時通知我」那一項通知設定） |
| 複製失敗 log | ⋯ →「複製失敗 log」：結論是 `failure` 或 `timed_out` 的 job，各取最後 200 行（設定可調 20–5000）複製到剪貼簿，不寫入任何檔案 |
| 等某一筆跑完 | 未完成或等待中的 run，⋯ →「這筆完成時通知我」，列上會顯示小鈴鐺；再點一次取消 |
| 靜音或強制納入 repo | 標題列的「repo 管理」，或系統匣右鍵「repo 管理」：列出所有看得到的 repo（開啟時另外抓一次協作 repo 清單）、類別、狀態與略過原因，可以靜音／取消靜音、強制納入／取消強制納入；頂端可以搜尋（`Ctrl+F`）與勾「只看略過」 |
| 設定 | 標題列的「設定」按鈕，或系統匣右鍵「設定」：認證方式、PAT、監看範圍、通知、失敗 log 行數、寫入操作（允許在 App 內重跑與取消 run，預設關閉）、開機自啟、收到系統匣、置頂、檢查新版本、語言；最下方是本專案 repo 的連結（用瀏覽器開啟 repo）、目前的版本，以及「授權與第三方聲明」（開啟 `LICENSE` 與 `THIRD-PARTY-NOTICES.md` 全文，可以捲動、選取複製，按 `Esc` 關閉；內容沒有翻譯。`IsItGreenYet-cli.exe notices` 也輸出同樣的內容，見[命令列](cli.zh-TW.md#notices)）。按「儲存」才生效，「取消」或 `Esc` 保持原樣。按「檢查連線」時，也會解除被 GitHub 以權限不足拒絕後停用的寫入（見[寫入功能需要的權限](authentication.zh-TW.md#寫入功能需要的權限)） |
| 換介面語言 | 設定頁的「語言／Language」選 English 或繁體中文，按「儲存」後整個程式立即換成新的語言（已經跳出的提示視窗、訊息條維持原本的語言）。第一次執行的預設依 Windows 顯示語言：中文是繁體中文，其他是英文。細節見[外觀與語言](#外觀與語言) |
| 開資料夾 | 系統匣右鍵「開啟資料夾」、設定頁的「開啟資料夾」，或「未預期錯誤」橫幅的「開啟資料夾」：用檔案總管開 `%LOCALAPPDATA%\IsItGreenYet` |
| 看到提示視窗時 | 螢幕右下角的提示：單筆提示點內文或空白處開該 run；彙總提示點某一行開那筆 run，點空白處（含「還有 N 筆」）開主視窗；新版本提示點內文或空白處開該 release 的頁面，和 run 合併時多一行，點那一行開該 release 的頁面；點了開啟之後提示就關掉。右上角 ✕ 關閉。滑鼠停在提示上時暫停倒數，移開後繼續剩下的時間 |
| 檢查新版本 | 設定頁「一般」的「定期檢查新版本（每 3 天）」預設開啟；關閉後完全不送檢查請求。有較新的 release 時跳出提示，同一個版本只跳一次。程式只通知：要升級就從該 release 的頁面下載新的 exe，結束程式，再替換同一個路徑的舊檔。什麼時候檢查、檢查失敗時會怎樣，見[行為規格](behavior.zh-TW.md#行為規格)的「檢查新版本」 |
| 收起來或結束 | 標題列的 ✕：預設收到系統匣，程式繼續執行。設定頁取消「關閉時收到系統匣」，或系統匣不可用（程式已降級成一般視窗）時，✕ 會直接結束程式；✕ 的 tooltip 會寫「收到系統匣」或「結束」。要真正結束請用系統匣右鍵「結束」 |

### 鍵盤

| 鍵 | 動作 |
|---|---|
| `F5` | 全量刷新 |
| `Ctrl+F` | 搜尋框（主畫面、repo 管理頁） |
| `Esc` | 主畫面：搜尋框有焦點時清空；否則不做事（不收起視窗，避免誤觸）。repo 管理頁：搜尋框有焦點而且有字時清空，否則關閉。設定頁：等於「取消」 |
| `Enter` | 主畫面：開啟選取列的 run。設定頁：「儲存」是預設按鈕 |
| `Shift+F10`／選單鍵 | 開啟選取列的右鍵選單 |

## 外觀與語言

### 字型

- 英文、數字與符號用 Consolas，中文與全形標點用微軟正黑體（介面版 `Microsoft JhengHei UI`）。兩個都是 Windows 內建的字型，程式只用名稱參照，不隨附任何字型檔（見 [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md)）。
- 粗體只用一個字重 `575`（`Design.xaml` 的 `FontWeight.Emphasis`）：Consolas 與微軟正黑體在這個字重都挑到字型本身的 Bold，沒有用演算法加粗的假粗體。
- 系統匣右鍵選單（WinForms）也照同樣的規則逐字挑字型，中英文的基線對齊。

### 主題與彈出畫面

- 深色主題，色票沿用 stop-annoying-me（SAM）。分支 chip、篩選與「自動更新」下拉、細進度條是膠囊外形（圓角是高度的一半）。
- 彈出畫面接近 Windows 11：系統匣右鍵選單、run 選單、篩選下拉、滑鼠停留提示、輸入框與捲軸的右鍵選單都是深色；選單、提示視窗與錯誤對話框的圓角、陰影與框線由 Windows（DWM）畫。Windows 10 不支援時是方角加框線。
- 錯誤對話框是程式自己的深色視窗（仿 Windows 11 的 ContentDialog）；對話框建立或顯示失敗，或對話框開著時又發生錯誤，才退回系統 MessageBox。

### 寬度不夠時

- 主畫面清單列依序隱藏：第二行的觸發者（視窗寬低於 `1047`）→ 第二行的分支 chip（低於 `957`）→ 時間細節（低於 `777`：第一行的開始時間，以及進行中的列的預估剩餘時間與進度條，只留已執行時間；進行中而且在取消中的列見[已知限制第 35 項](known-limitations.zh-TW.md)）。預設寬度 `1000` 時觸發者已經隱藏。
- 觸發者與分支隱藏後仍在第二行的 tooltip 與報讀名稱裡；時間細節隱藏後看不到開始時間與預估剩餘時間，要把視窗拉寬。
- 一般的資料在三項都隱藏之後還放不下才截斷；run 超過預估（英文的「~3m over estimate」比較長）、repo 或分支名稱偏長時，斷點之間也可能截斷（[已知限制第 28 項](known-limitations.zh-TW.md)）。截斷的地方滑鼠停留看全文。
- 摘要列放不下時整段換到下一行，不在一段中間斷開。
- repo 管理頁的名稱欄太窄時（英文 `620`、中文 `530` 以下；`630`、`540` 仍是寬版，量測每 10 DIP 一格），類別、狀態與兩個按鈕換到名稱下方。
- 斷點的量測方式與數字見 [design-notes.md](design-notes.md) 的「寬度斷點的量測」與「repo 管理頁的窄版」。

### 介面語言

- 繁體中文與 English。設定頁的「語言」卡片（標題附上另一種語言：「語言／Language」），按「儲存」後生效，存在 `settings.json` 的 `language`（`zh-Hant`／`en`）。
- 預設：第一次執行（沒有 `settings.json`）時，Windows 顯示語言是任何一種中文就用繁體中文，其他用英文；`settings.json` 已經存在但沒有這個欄位、值不認得，或設定檔損毀回復成預設值時，用繁體中文。
- 儲存後整個程式立即換成新的語言：主畫面、系統匣選單與 tooltip、開著的 repo 管理頁、監看引擎產生的橫幅與問題標示（下一份快照）。已經關掉的一次性提示不會因為換語言又出現。
- 不會立即換的：已經跳出的提示視窗、訊息條、設定頁的錯誤與檢查連線結果、已經複製的失敗 log（都是當時的結果）；上一次執行留下、這次還沒重新判定的 repo 問題標示；WPF 內建的輸入框右鍵選單（剪下／複製／貼上），重新啟動後才保證是設定的語言。
- 沒有翻譯的：`api.log`、`error.log` 的內容，以及程式內部錯誤（程式寫錯才會出現）的例外訊息，維持中文；.NET 本身的例外訊息一律是英文；Windows 系統錯誤的說明（例如認證管理員、開機自啟失敗的原因）由 Windows 決定語言，推測是 Windows 顯示語言。
