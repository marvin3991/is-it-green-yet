## Overview

See the GitHub Actions runs of your repos and your organizations' repos at a glance, mainly to check whether CI is green yet. A Windows tool (WPF/.NET 10) that stays in the system tray.

The tray icon's color and shape answer "is anything red, is anything running?" without opening a window.

- **Tray**: a ✕ on red if anything failed, a "…" on yellow if anything is in progress or queued, a ✓ on teal if everything succeeded; a "!" badge is added when there's a connection problem.
- **Main window**: the latest 30 runs of each monitored repo, with filters, search, and a needs-attention-only view; in-progress runs show elapsed time and estimated time remaining.
- **Notifications**: when a tracked run fails, a run you triggered succeeds, a run you marked finishes, or a new version is available, a notification pops up at the bottom right of the screen without stealing focus.
- **Saves quota**: polling sends only `GET` requests, with an ETag when it has one; when nothing has changed, GitHub returns 304, which doesn't count against the primary quota.
- **Re-run and cancel (off by default)**: after you turn on write actions in Settings, the run menu can re-run failed jobs, re-run all jobs, cancel, or force cancel, with a confirmation every time. The app is read-only by default and sends `POST` requests only after write actions are turned on.
- **Command line**: `IsItGreenYet-cli.exe status --json` reads the status written by the app, prints one line of JSON, and reports the overall status through its exit code (matching the tray), for use in scripts.
- **Authentication**: reuses your gh CLI sign-in, or uses a fine-grained PAT instead (read-only permissions are enough if you only want to see status).
- **Interface language**: Traditional Chinese or English, switched in Settings; the change applies as soon as you click "Save".
- **No installer**: a single executable; once the .NET 10 Desktop Runtime is installed (see [System requirements](../README.md#system-requirements) in the README), copy it to a folder and run it. Don't put it in a folder that other people or your browser can write to (such as Downloads): a DLL or `gh.exe` with a matching name next to the exe gets loaded.

## Scope

- **GitHub Actions workflow runs only.** External checks outside Actions (for example, check runs or commit statuses that services such as Cloudflare or Zeabur attach to PRs) are out of scope.
- **Read-only by default**: only `GET` requests are sent. Only after you turn on write actions in Settings can you re-run and cancel runs from the run menu (this sends `POST`, and the token needs write permission; see [Permissions for write actions](authentication.md#permissions-for-write-actions)).
- No single-job re-runs, no bulk re-run or cancel of multiple runs at once, and no re-run or cancel buttons in notifications or the tray menu.
- No webhooks: a webhook needs a publicly reachable receiver, which a desktop tray app doesn't have, so polling is the only option.
- No per-workflow muting (muting is repo-level only) and no installer. The app tells you about new versions but never downloads or replaces itself: to upgrade, you replace the exe.

## Common tasks

| To do this | Do this |
|---|---|
| See the overall status | Look at the tray icon: a ✕ on red for failures, a "…" on yellow for in progress or queued (including waiting for approval), a ✓ on teal when everything succeeded, and a "–" on gray for no data. On the first run or after the cache database is rebuilt, it stays gray instead of turning teal until the repo list and every repo have been checked (failures and in-progress runs still show; for the exception when a catch-up fetch fails, see item 33 in [Known limitations](known-limitations.md)); if the list keeps failing it stays gray, and a single repo that can't be checked holds it for at most 1 hour. A "!" badge at the bottom right means a connection problem (signed out, rate limited, offline, GitHub keeps returning 5xx, or the API version is no longer supported). Hover over the icon for the tooltip: the first line is `IsItGreenYet`, the second is "N in progress · M failed · Updated HH:mm", plus one more line with the reason when there's a connection problem or repos that can't be updated; right after startup, before the first data arrives, it shows only `IsItGreenYet` |
| Open the main window | Left-click the tray icon, or right-click it and choose "Open"; running the exe again while the app is already running also brings back the existing window. The command line `IsItGreenYet-cli.exe` is a separate executable that doesn't go through the app's single-instance check, so running it doesn't bring back the window (see [Command line](cli.md)) |
| Tray context menu | 7 items, in order: Open \| Refresh now, Pause auto-refresh (shows "Resume auto-refresh" while paused) \| Repo manager, Settings, Open folder \| Exit ("\|" is a separator line in the menu). Like the main window, the menu is dark, with rounded corners and a shadow on Windows 11 |
| Filter the list | Six multi-select filters in the filter bar: Repo, Workflow, Event, Status, Branch, and Actor. Choices within one field are combined with "or", and different fields with "and"; when something is checked, the button shows the count, for example "Repo (2)". While any filter, search, or "Needs attention only" is active, "Clear filters" appears at the end of the filter bar. Filter preferences are saved; search text isn't. Filters affect only the list, not the counts in the summary bar or the tray |
| Search | `Ctrl+F`; matches the repo, title, workflow name, and branch, case-insensitively. Press `Esc` while the search box has focus to clear it |
| Show only what needs action | Check "Needs attention only": tracked runs that failed, plus all unfinished runs and runs waiting for approval |
| Refresh now | `F5`, "Refresh now" in the tray menu, or "Retry now" on the banner (shown only when offline or when GitHub is returning errors) |
| Adjust auto-refresh | The "Auto-refresh" drop-down on the right of the summary bar: Auto (default), 30 sec, 1 min, 5 min, Paused. **A fixed interval replaces the intervals of Auto mode**: the push probe, each repo's runs polling (including repos that Auto mode polls every 15 seconds while a run is in progress), and the single-run updates for tracked runs and runs marked "Notify me" all switch to that interval, so with "5 min" a new run can take up to about 5 minutes to appear. The PR list, the workflow list, and the full repo list keep their usual cycles, and the longer intervals when quota runs low and the minimum interval while the screen is locked still apply. "Paused" stops all periodic polling; only F5 / "Refresh now", the command-line `--refresh`, and unlocking, waking, coming back online, or signing back in run a full refresh, once. You can pause/resume from the tray menu (resume returns to the mode used before pausing). The choice is saved in `settings.json` and kept across restarts, including Paused. The check for new versions has its own setting and still runs while Paused (see "Check for new versions" below) |
| Open web pages | Click a repo name to open that repo's Actions page; click the PR number or commit in the trigger description, or a branch chip, to open the matching page; select a row and press `Enter` to open that run. Only URLs starting with `https://github.com/` are opened; any other URL isn't opened, a message is shown, and it's written to error.log |
| More actions | The ⋯ button at the right end of each row, a right-click, or `Shift+F10`: Open run, Open pull request (when there's a PR number), Open commit, Copy run URL, Copy failed logs (failed runs), Notify me (unfinished or waiting runs), and Mute this repo. With write actions turned on, these are followed by a separator and three more items, "Re-run failed jobs", "Re-run all jobs", and "Cancel run", plus "Force cancel", which appears only when a cancellation was accepted more than 5 minutes ago and the run still hasn't finished (see the next row). With write actions turned off (the default), neither these items nor the separator appear |
| Re-run or cancel a run | First, in Settings under "Write actions", check "Allow re-running and cancelling runs" and save (off by default; while it's off, no `POST` is sent). When you pick one of these items in the ⋯ menu, a confirmation dialog states which run it is (`repo · workflow #number`, the attempt, and the branch) and what the action will do. Focus starts on "No", so `Enter` doesn't carry out the action, and `Esc` is the same as "No". After you confirm, the message bar shows "Sending…". Accepted requests (for example, "Re-run requested.") and requests that weren't sent (for example, "You're offline, so nothing was sent.") appear in the message bar; requests rejected by GitHub and uncertain results (no response received, or GitHub returned 5xx: the action may already have taken effect, and the app checks automatically) appear in an error dialog. Items you can't use right now are disabled; hover over one to see why (for example, "Not finished yet", "Already finished", "The workflow is disabled", "More than 30 days old", "May have reached the re-run limit", "Offline", or "Missing permission"). After a cancellation is accepted, the row's status and time columns show "Cancelling" until the run actually finishes (it's no longer shown after the app restarts; for in-progress rows when the window is narrower than `777`, see item 35 in [Known limitations](known-limitations.md)). For a run re-run in the app, a notification pops up automatically when the new attempt finishes (following the **Notify when a run marked "Notify me" finishes** notification setting) |
| Copy failed logs | ⋯ → "Copy failed logs": for each job whose conclusion is `failure` or `timed_out`, the last 200 lines (adjustable from 20 to 5000 in Settings) are copied to the clipboard; nothing is written to a file |
| Wait for one run to finish | For an unfinished or waiting run, ⋯ → "Notify me"; a small bell appears on the row. Choose it again to cancel |
| Mute or force-include a repo | "Repo manager" in the title bar or in the tray menu: lists every repo you can see (fetching the collaborator repo list once more when it opens), with its category, status, and skip reason; you can Mute/Unmute and Force include/Stop forcing. At the top you can search (`Ctrl+F`) and check "Skipped only" |
| Settings | The "Settings" button in the title bar, or "Settings" in the tray menu: sign-in method, PAT, monitoring scope, notifications, failed log line count, write actions (allow re-running and cancelling runs in the app; off by default), Start with Windows, Close to tray, Keep the window on top, check for new versions, and language; at the very bottom, a link to this project's repo (opens the repo in your browser), the current version, and "License and third-party notices" (opens the full text of `LICENSE` and `THIRD-PARTY-NOTICES.md`, which you can scroll, select, and copy; `Esc` closes it. The text isn't translated: the notices are mostly in Traditional Chinese. `IsItGreenYet-cli.exe notices` prints the same text; see [Command line](cli.md#notices)). Changes take effect only when you click "Save"; "Cancel" or `Esc` leaves everything as it was. Clicking "Check connection" also re-enables writes that were disabled after GitHub rejected them for insufficient permissions (see [Permissions for write actions](authentication.md#permissions-for-write-actions)) |
| Change the interface language | In Settings, choose English or 繁體中文 under "Language / 語言" and click "Save"; the whole app switches to the new language right away (notifications and the message bar already on screen keep their original language). On first run, the default follows the Windows display language: Traditional Chinese for Chinese, English for anything else. Details in [Appearance and language](#appearance-and-language) |
| Open the data folder | "Open folder" in the tray menu, "Open folder" in Settings, or "Open folder" on the unexpected-error banner: opens `%LOCALAPPDATA%\IsItGreenYet` in File Explorer |
| When a notification appears | Notifications appear at the bottom right of the screen. In a single-run notification, click the text or a blank area to open that run; in a summary notification, click a line to open that run, or click a blank area (including "N more") to open the main window. In a new-version notification, click the text or a blank area to open that release's page; merged with run notifications, it's one more line, and clicking that line opens the release's page. The notification closes once you open something. The ✕ at the top right closes it. Hovering over a notification pauses its countdown; moving the pointer away resumes the remaining time |
| Check for new versions | In Settings, under "General", "Check for new versions every 3 days" is on by default; when it's off, no check request is sent at all. When a newer release exists, a notification pops up, once per version. The app only notifies: to upgrade, download the new exe from the release's page, exit the app, and replace the exe at the same path. For when it checks and what happens when a check fails, see "Check for new versions" under [Behavior](behavior.md#behavior) |
| Hide or exit | The ✕ in the title bar: by default it closes to the tray and the app keeps running. If you uncheck "Close to tray" in Settings, or if the tray isn't available (the app has fallen back to a normal window), ✕ exits the app; the ✕ tooltip says "Close to tray" or "Exit". To really exit, use "Exit" in the tray menu |

### Keyboard

| Key | Action |
|---|---|
| `F5` | Full refresh |
| `Ctrl+F` | Search box (main window, Repo manager) |
| `Esc` | Main window: clears the search box when it has focus; otherwise does nothing (it doesn't hide the window, to avoid accidents). Repo manager: clears the search box when it has focus and contains text; otherwise closes the window. Settings: same as "Cancel" |

## Appearance and language

### Fonts

- English text, digits, and symbols use Consolas; Chinese and full-width punctuation use Microsoft JhengHei (the UI variant, `Microsoft JhengHei UI`). Both are fonts built into Windows. The app refers to them only by name and ships no font files (see [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md) (Traditional Chinese)).
- Bold uses a single weight, `575` (`FontWeight.Emphasis` in `Design.xaml`): at this weight, both Consolas and Microsoft JhengHei pick the font's own Bold face, with no algorithmic faux bold.
- The tray context menu (WinForms) also picks fonts character by character with the same rule, so Chinese and English text share the same baseline.

### Theme and pop-ups

- Dark theme, with the color palette taken from stop-annoying-me (SAM). Branch chips, the filter and "Auto-refresh" drop-downs, and the thin progress bar are pill-shaped (the corner radius is half the height).
- Pop-ups look close to Windows 11: the tray context menu, run menu, filter drop-downs, hover tooltips, and the context menus of text boxes and scroll bars are all dark; the rounded corners, shadows, and borders of menus, notification windows, and error dialogs are drawn by Windows (DWM). On Windows 10, which doesn't support this, they have square corners with a border.
- The error dialog is the app's own dark window (modeled on the Windows 11 ContentDialog). The app falls back to the system MessageBox only if the dialog fails to be created or shown, or if another error occurs while the dialog is open.

### When the window is narrow

- Rows in the main window list hide items in this order: the actor on the second line (window narrower than `1047`) → the branch chip on the second line (narrower than `957`) → time details (narrower than `777`: the start time on the first line, plus the estimated time remaining and the progress bar on in-progress rows, leaving only the elapsed time; for rows that are in progress and being cancelled, see item 35 in [Known limitations](known-limitations.md)). At the default width of `1000`, the actor is already hidden.
- After they're hidden, the actor and branch are still in the second line's tooltip and in the row's accessible name; after time details are hidden, the start time and estimated time remaining can't be seen, so you need to widen the window.
- Typical data is truncated only if it still doesn't fit after all three are hidden. When a run is over its estimate (the English text "~3m over estimate" is longer than the Chinese), or a repo or branch name is long, text may also be truncated between breakpoints (item 28 in [Known limitations](known-limitations.md)). Hover over truncated text to see it in full.
- When the summary bar doesn't fit, whole segments wrap to the next line; a segment is never split in the middle.
- When the name column in Repo manager gets too narrow (`620` and below in English, `530` and below in Chinese; `630` and `540` are still the wide layout, measured in 10 DIP steps), the category, status, and two buttons move below the name.
- For how the breakpoints were measured and the numbers, see "寬度斷點的量測" (measuring the width breakpoints) and "repo 管理頁的窄版" (the narrow layout of Repo manager) in [design-notes.md](design-notes.md) (Traditional Chinese).

### Interface language

- Traditional Chinese and English. Set it in the "Language" card in Settings (the card title also shows the other language: "Language / 語言"); it takes effect when you click "Save", and is stored as `language` in `settings.json` (`zh-Hant`/`en`).
- Default: on first run (no `settings.json`), Traditional Chinese if the Windows display language is any form of Chinese, otherwise English. If `settings.json` already exists but has no such field, has a value the app doesn't recognize, or the settings file was corrupted and reset to defaults, Traditional Chinese is used.
- After you save, the whole app switches to the new language immediately: the main window, the tray menu and tooltip, Repo manager if it's open, and the banners and problem labels generated by the monitoring engine (from the next snapshot). One-time notices you've already dismissed don't come back because of a language change.
- Not switched immediately: notifications already shown, message bars, errors and "Check connection" results in Settings, and failed logs already copied (these are all results from that moment); repo problem labels left over from the previous run that haven't been re-evaluated in this run yet; and WPF's built-in text box context menu (Cut/Copy/Paste), which is only guaranteed to be in the configured language after a restart.
- Not translated: the contents of `api.log` and `error.log`, and exception messages for internal program errors (which appear only when there's a bug), stay in Chinese; .NET's own exception messages are always in English; descriptions of Windows system errors (for example, the reason Credential Manager or Start with Windows failed) are in a language Windows chooses, presumably the Windows display language (speculative).
